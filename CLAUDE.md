## Project

DACE (*Diversity-Driven Adversarial Co-Evolution for Robust LLM Safety Alignment*, NeurIPS 2026) trains an attacker LLM and a defender LLM in an alternating GRPO game. On top of attacker–defender co-evolution it adds (1) a 12 risk × 10 style attack strategy grid with a normalized marginal coverage-gain reward for the attacker, and (2) a Bayesian (Beta–Bernoulli) adversarial replay pool with time decay, Thompson sampling and pruning for the defender.

## Layout

- `src/360-LLaMA-Factory/` — Phase 1 attacker SFT (`examples/train_full/*_v4_full_sft_dsz2.yaml`, data registered in `data/dataset_info.json`).
- `src/verl/` — Phase 2 multi-agent RL.
- `scripts/rl/` — training launchers; `scripts/model_merge.sh` converts FSDP checkpoints to HF.
- `data/safety/` — RL seed prompts + `preprocess_dace.py`; `data-sft/` — optional SFT CoT distillation pipeline.
- `prompt/game/` — attacker / defender system prompts.
- `eval/` — Table 1/2/3 evaluation (`safety-eval-fork`, `olmes`, `OpenRT`); see `eval/README.md`.

Entry chain:
```
scripts/rl/train_dace_<backbone>.sh
  → scripts/rl/train_dace.sh
    → python -m verl.separated_trainer.main_ppo
      → RayReMASeparatedTrainer (verl/separated_trainer/ppo/ray_trainer.py)
```

DACE core files (under `src/verl/verl/`):
- `separated_trainer/ppo/archive_pool.py` — strategy grid, strategy parsing, coverage-gain reward, replay pool (posterior update, decay, prune, Thompson sampling).
- `separated_trainer/ppo/ray_trainer.py` — diversity-reward injection, replay batch construction, stage transitions.
- `separated_trainer/ppo/multi_agent_rollout.py` — skips attacker generation for replayed samples.
- `workers/reward_manager/game.py`, `utils/reward_score/game.py` — judge calls (Qwen3Guard served as `orm`), harm / refusal / format rewards.
- `separated_trainer/config/ppo_trainer.yaml` — Hydra defaults (`algorithm.diversity`, `algorithm.replay_pool`).

## Data format

`data/safety/train_dace.parquet` / `test_wjb_dace.parquet` (generated by `preprocess_dace.py`) have the fields `data_source`, `prompt`, `ability`, `reward_model`, `extra_info`, `question`, `data_type` (`vanilla_harmful` / `vanilla_benign`), `adversarial`. SFT data uses LLaMA-Factory alpaca format (`instruction` / `input` / `output` / `system`).

## Rules
